## 宿主升级要求

- 保持旧截图流程不需要新增参数。新多屏流程需要每次调用 `capture({ interactionMode: 'live', display: 'all' })`，仅在 Windows 10 2004+ / macOS 14+ 启用。
- 吸附需要主进程创建对应平台 provider，并传给 `managerOptions.getWindowSnapRegions`；只选整窗时显式设 `granularity: 'window'`，省略则是 `panel`。直接构造 `ScreenshotManager` 时，`getWindowSnapRegions` 放在构造参数顶层。
- Mac 权限由宿主通过 `getPermissions()` 查询、通过用户操作调用 `getPermissions(true)` 请求；需要“两个权限未齐就禁止截图”的产品，应由宿主阻止开始截图。库默认允许缺少 AX 权限时降级。
- 正式宿主解包 `node_modules/electron-snapora/dist/native/**` 并完成签名；标准 npm 布局无需传原生程序路径，也不依赖 demo。详细接入和清理见 [中文 README](../../README.zh-CN.md)。

## 发布产物

main 的 CI 会编译 Windows 预编译 exe 和 macOS arm64/x86_64 通用 helper，在 macOS 上生成完整 `.tgz`，输出为 `electron-snapora-npm-<commit SHA>` artifact。必须确认对应提交的所有 CI 检查通过后使用此产物。

Windows 无法从 Swift 源码编译 Mac helper；本地从源码发布前必须补齐与该提交一致的 Mac universal 产物。当前机器已从验证通过的 CI 包补齐到 `src/electron/native` 和 `dist/native`，但该文件不受 Git 跟踪，其他机器不会自动获得。发布优先使用完整 CI tarball，保留 Mac 可执行权限，不要解包后重新打包。

## 正式发布前

1. 确认最终 main 提交的 CI 全绿，下载其 npm artifact，并核对压缩包包含 `dist/native/snapora-macos`、两个 Windows exe 和 `windows-helpers.json`。
2. 在干净目录针对这个已验证的 tarball 执行 `npm publish ./electron-snapora-1.0.26.tgz --dry-run --access public --tag latest --registry=https://registry.npmjs.org/`，确认名称、版本和文件清单。
3. 完成 Mac 实机权限与截图验收，确认 npm 账号、发布权限和 2FA。只有正式发布指令后才执行不带 `--dry-run` 的 publish。
4. 发布成功后，在同一验证提交创建 `v1.0.26` tag 和同名 GitHub Release；正文只使用本版 changelog。随后再更新宿主正式依赖。

本次准备不创建版本 tag、不创建 GitHub Release，也不发布 npm。

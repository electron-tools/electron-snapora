## Scope

This patch addresses stale Windows display-to-capture-source mappings that can swap monitor contents, and removes ambiguous multi-monitor matching by array position or source ID. Normal captures retain the existing source-ID cache and shared prewarming request. Display changes, resume, and unlock invalidate that cache; work-area-only changes do not.

Both stream and image capture paths use `display_id`. If multiple monitors cannot be matched reliably, capture fails with `DISPLAY_NOT_FOUND`. The unambiguous single-display fallback is retained. The default manager releases its adapter's system subscriptions on disposal; hosts retain ownership of injected adapters.

No changes were made to Canvas rendering or overlay window display timing. The demo's repeat-capture flicker also occurs with the original code and is not claimed as fixed in this release.

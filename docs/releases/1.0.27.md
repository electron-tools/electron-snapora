# electron-snapora 1.0.27 发布流程

本版仅补充五种语言的宿主接入文档，运行时代码与 1.0.26 相同。版本号固定为 `1.0.27`，发布到 npm `latest`。

1. 提交版本和文档，等待对应提交的 CI 全部通过。
2. 下载该提交的 `electron-snapora-npm-<SHA>` artifact。确认 tarball 的版本为 `1.0.27`，包含五语升级说明、Windows 两个 exe、清单和 macOS arm64/x86_64 universal helper，并保留 Mac 执行权限。
3. 使用完整 CI tarball 执行发布预演，再正式发布，不在 Windows 源码目录直接执行无参数 `npm publish`：

   ```powershell
   npm publish ./electron-snapora-1.0.27.tgz --dry-run --access public --tag latest --registry=https://registry.npmjs.org/
   npm publish ./electron-snapora-1.0.27.tgz --access public --tag latest --registry=https://registry.npmjs.org/
   ```

4. 从 npm registry 确认 `1.0.27` 存在、`latest` 指向它、发布包完整性与验证产物一致，之后才执行：

   ```powershell
   npm deprecate electron-snapora@1.0.26 "Please upgrade to 1.0.27+ for complete host integration documentation. Runtime behavior is unchanged." --registry=https://registry.npmjs.org/
   ```

5. 核验 registry 中的弃用提示，在已验证的发布提交上创建 `v1.0.27` tag 和 GitHub Release。

若发布失败或需要完成 npm 认证，保留 1.0.26 状态不变，完成发布后再弃用。`deprecate` 不是删除，也不能释放版本号用于重复发布。

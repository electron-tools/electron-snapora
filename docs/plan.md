# Electron Snapora 任务执行计划

> 创建时间：2026-08-18
> 计划目标：交付一套可被不同 Electron 应用快速接入、低配置、无原生编译依赖的截图与标注 npm 包。
> 详细设计：[implementation-plan.md](./implementation-plan.md)

## 状态约定

- `[ ]`：未开始
- `[-]`：进行中
- `[x]`：已完成并通过对应验收
- `[!]`：受阻，必须在任务后记录原因和解除条件

## 完成定义

单个任务只有同时满足以下条件才能标记完成：

1. 公共接口具有明确的 TypeScript 类型，Electron 内部能力不泄漏到 Renderer。
2. 复杂生命周期、跨进程通信和平台差异具有简洁中文注释。
3. 核心分支有自动化测试；临时验证代码不进入仓库。
4. `pnpm lint`、`pnpm typecheck`、`pnpm test` 和 `pnpm build` 全部通过。
5. 新增公共能力同步更新 README 或设计文档。

## 风险与约束

| 风险                                | 处理策略                                              |
| ----------------------------------- | ----------------------------------------------------- |
| Electron API 在不同版本存在行为差异 | 依赖能力检测和适配器，不通过版本号分支耦合实现        |
| 多显示器源 ID 无法稳定匹配          | 严格匹配 `display_id`，失败时返回 `DISPLAY_NOT_FOUND` |
| Overlay 被截入最终图片              | 必须先完成静态屏幕捕获，再创建并显示 Overlay          |
| 截图任务重复结算或监听器泄漏        | Session 只允许一次结算，所有退出路径统一清理          |
| Overlay 首帧未解码或布局未稳定      | Renderer 发出 `prepared(jobId)` 后主进程才显示窗口    |
| 透明窗口的动画帧被宿主或系统节流    | 每次合成帧最多等待 60ms，不让准备阶段无限阻塞         |
| Windows 首次显示把窗口限制到工作区  | 透明预热后重设完整显示器 `bounds`，再显现 Overlay     |
| Overlay 被其他置顶应用覆盖          | 预热和显现时使用 `screen-saver` 层级并刷新原生 Z 序   |
| DPI 导致视觉选区与图片像素错位      | 图形模型统一使用 Image Pixel，按实际捕获尺寸换算      |
| 不同字符宽度导致文字框选偏差        | 以实际 Canvas 字体执行 `measureText()` 并保存布局指标 |
| textarea 与 Canvas 基线位置不一致   | 将边框、内边距和半行留白按 DPI 换算为首行基线坐标     |
| 整屏降采样导致马赛克块偏色或过大    | 固定 8px 网格，仅对框选周边执行高质量平均色采样       |
| npm 打包后资源路径变化              | 资源定位集中到单一模块，并对发布目录做打包检查        |
| 宿主 Renderer 越权调用截图 IPC      | 强制顶层 Frame 校验，并由宿主显式授权非 `file:` 来源  |
| 非法截图参数进入 Overlay            | IPC 边界执行运行时解析，只传递白名单化后的配置        |
| 主进程被打包后 `__dirname` 失真     | 独立消费项目验证 external 与资源复制，并提供诊断错误  |
| Electron 版本声明与 Node 目标不一致 | 以自动化矩阵决定最低版本，不声明未经验证的兼容范围    |
| 4K/8K 截图造成内存峰值过高          | 限制像素数与 IPC 字节数，建立压力测试                 |

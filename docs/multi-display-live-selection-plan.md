# 多屏实时选区与选后采集方案

日期：2026-10-30。状态：设计方案，尚未实现。本次只整理方案；实现范围为 electron-snapora 和 demo，Ping 接入保持不变。

## 目标与交互约定

一次启动截图，在所有屏幕上嗅探、预览和选择；用户确定选区后，才采集选中屏幕并进入标注。选区限制在一块屏幕内，不做跨屏拼接。

这里的“像 Lark”指用户描述的交互效果，未确认 Lark 的内部捕获时序或实现技术。

| 阶段                | 用户看到的内容                           | 后台动作                                              |
| ------------------- | ---------------------------------------- | ----------------------------------------------------- |
| 启动                | 原桌面上出现轻量遮罩、光标与候选边框     | 每屏显示透明交互层，读取窗口/UIA 边界；不抓取桌面像素 |
| 跨屏悬停            | 鼠标所在屏幕显示吸附预览                 | 按屏幕分发候选，保留 window/panel/fine 三档           |
| 单击候选 / 拖动框选 | 固定选区                                 | 鼠标抬起且选区有效时，主进程锁定 displayId 和选区     |
| 选后采集            | 选区和遮罩保持，其他屏幕退出截图交互     | 仅请求选中屏幕的新画面，采集期间屏蔽重复提交          |
| 标注                | 选中屏幕切换成已冻结画面，显示现有工具栏 | 复用标注、调整选区、复制、保存、贴图流程              |
| 完成 / Esc          | 所有屏幕恢复正常                         | 结束整个会话，取消查询与捕获，释放输入和临时资源      |

具体行为：

- 没有按下鼠标时，可自由往返 A、B 屏；只在当前屏幕显示嗅探边框。
- 拖动开始后锁定起点屏幕，越界部分裁到该屏边缘；另一屏不另起选区。pointer cancel 放弃该次拖动；小于最小尺寸的选区回到嗅探。
- 选区首次确定后进入截图/标注阶段；后续移动或缩放选区都基于这张冻结图，不重新抓取实时桌面。重新选择其他屏幕需要取消并重新启动。
- 底层页面在选择阶段仍可自行播放视频、刷新或展示通知。图片来自选区提交后获得的帧，不是快捷键按下时的画面，也不保证与鼠标抬起时刻完全一致。
- 实时阶段暂不提供依赖截图像素的放大镜、像素颜色值；坐标和选区尺寸照常可用。需要像素取色时进入冻结图阶段。这避免为取色偷偷提前开启全屏捕获。

## 当前实现与需要调整的位置

现有链路是 `ScreenshotSession → capture → initialize(frames) → drawCapturedFrame → image-ready → 选择/标注`。
Windows 主进程先取得 desktop-source，真正的像素读取发生在 Overlay 的 `getUserMedia` 与 Canvas 绘制中。
因此不是简单把主进程中的一个 `capture()` 调用往后移动：选区状态目前也依赖已加载的图片。

| 文件/模块                                                                           | 调整意图                                                                               |
| ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `src/electron/main/screenshot-session.ts`                                           | 从单 Overlay 改成同一 job 下的多屏窗口集合；先选择后捕获，只有一个窗口可以成为标注窗口 |
| `src/electron/main/screenshot-manager.ts`                                           | 管理多屏窗口缓存及统一清理；一个截图会话仍受现有 busy/queue 约束                       |
| `src/electron/main/overlay-window.ts`                                               | 支持透明实时选择阶段、排除捕获，以及同窗口切换到冻结图标注阶段                         |
| `src/electron/main/electron-capture-adapter.ts`                                     | 保留按 displayId 的单屏捕获；直到有效选区提交才开始获取像素                            |
| `src/electron/protocol/*`、`src/electron/preload/overlay-preload.ts`                | 区分选择初始化、选区提交、图片初始化；所有消息带会话及屏幕标识                         |
| `src/overlay/selection-store.ts`、`src/overlay/main.ts`                             | 让无图片时也能嗅探/框选；图片就绪后保留刚确定的选区而不是重置                          |
| `src/electron/main/windows-snap-provider.ts`、`src/electron/native/windows-snap.cs` | 排除本次截图层，补充实时阶段候选刷新，保持查询可取消                                   |
| `demo/*`、`test/*`                                                                  | demo 开启新模式，增加多屏与实时选区回归                                                |

## 会话和窗口设计

```text
创建会话
  → 显示各屏透明选择层
  → selecting（允许跨屏悬停）
  → capturing（锁定一个 displayId + rect）
  → editing（仅该屏显示冻结图）
  → exporting
  → completed / cancelled / failed
```

主进程持有 `Map<displayId, OverlayWindow>`、屏幕几何快照、会话状态和唯一的选择结果。
各屏只持有自己的临时悬停和拖动状态，不各自创建独立 ScreenshotSession，不允许多屏分别导出。

选择初始化只包含 jobId、displayId、该屏 DIP 边界、缩放、工具配置和候选；不要求 `frames`。
选区提交携带 jobId、displayId 和屏幕内 DIP 矩形。主进程验证发送方属于该屏窗口、主 frame、会话阶段、有限数值和边界；第一次有效提交原子锁定，其他窗口的迟到提交丢弃。

图片初始化再携带捕获帧和初始选区。沿用当前标注 Canvas，但须单独处理“保留初始选区”，不能照搬当前初始化时清空选区的逻辑。
只有选中窗口可调用输出 IPC；其他屏幕不能取得其图像或提交输出。

所有异步结果同时核对 jobId、显示拓扑版本和捕获请求状态。Esc、宿主退出、选中屏幕移除后，迟到帧不得再次显示窗口。
切屏悬停不反复抢系统焦点；鼠标事件在各屏处理，键盘取消作用于整个会话。点击选区锁定前不唤起工具栏。

## 减少闪烁的核心：交互层不进入截图

只推迟采集仍然可能把遮罩、候选边框或光标截进图片。首选验证路径为：

1. 每个 Windows 交互窗口在首次显示前，由 Electron 主进程调用 `setContentProtection(true)`。
2. 全程使用透明窗口，只绘制轻量 UI；实时选择期间不显示桌面截图 Canvas、不开启桌面视频流。
3. 选区确定后，交互层保持可见，请求选中显示器的画面。捕获结果必须排除所有截图交互层。
4. 图片准备好后，在选中屏的同一窗口中接入冻结图，并一次切换遮罩、选区和工具栏，避免销毁重建全屏窗口。

Electron 文档说明该接口在 Windows 使用 `WDA_EXCLUDEFROMCAPTURE`；其生效要等下一次桌面合成，不能把调用返回当成“已生效”。Windows 10 2004 以前可能得到黑色窗口，而不是移除窗口。不能用 `isContentProtected()` 的布尔值替代实际像素验证。[Electron BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window/#winsetcontentprotectionenable-macos-windows)、[Microsoft SetWindowDisplayAffinity](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)

当前包声明 Electron >=42，开发依赖为 43.3.0；最新文档不代替这些版本的实际测试。必须用当前 `getUserMedia` 捕获路径验证排除效果，并测试快速点击时的合成竞态。
如果此路径验证不通过，先评估原生捕获后端或禁用新模式；不把“隐藏全部窗口再显示”的有闪烁兜底当成无闪烁功能交付。

macOS/Linux 暂不启用本方案。旧 frozen 单屏模式保留。新模式是减少闪烁的设计目标，不提前承诺所有显卡、HDR 或远程桌面环境都零闪烁。

## 采集范围和坐标

首版在选择后读取**所选屏幕的一帧完整画面**，供现有编辑器使用，导出时裁剪选区。这既满足“选后才采集”，也保留选后扩大、移动选区的能力；不会同时采集其他屏幕。
原生按矩形直接抓图可单独评估，不是本次必需项。现有 Electron 捕获接口不应被文档化成已支持原生矩形抓取。

几何统一采用全局 Screen DIP；各屏渲染前减去本屏原点；导出按该帧实际像素尺寸换算，不能复用主屏缩放系数。
处理负原点、上下排列、混合 DPI；像素左/上边界向下取整，右/下边界向上取整并裁到真实图像范围。
跨屏窗口的 UIA 区域在各屏独立裁剪，点击只选择当前屏幕内可见部分。
首版在显示器增删、位置或缩放改变时结束当前会话并允许重试，避免正在拖动时静默迁移坐标。

## 实时嗅探与预热

预热内容为隐藏的选择窗口、静态页面资源、原生查询 worker 和显示器 source ID；不预取屏幕像素。
当前 source ID 枚举已采用 `thumbnailSize: { width: 0, height: 0 }`。Electron 官方将这一配置用于避免缩略图捕获处理。[desktopCapturer](https://www.electronjs.org/docs/latest/api/desktop-capturer)

现有嗅探候选是单次快照，实时桌面会变化，不能只复用这一快照到会话结束：

- 窗口边界先到先用，UIA 容器随后补充；保持当前三档过滤策略。
- 优先当前鼠标所在屏幕/目标窗口，鼠标移动只做本地命中，不逐事件扫描全桌面。
- 首版采用节流刷新窗口几何并按进入窗口、候选过期刷新容器；同一时刻最多一个 native 查询，合并重复请求，用请求序号丢弃过期结果。
- 新候选只更新空闲悬停，鼠标按下后锁定本次候选；提交选区后停止嗅探。
- 通过本次交互层的 HWND 精确排除自身，不能排除整个进程，否则宿主自身窗口也无法被截。若按点查询，必须避开最上层交互窗口，基于底层目标窗口树查找。
- UIA 慢或不可用时继续允许窗口级选择及手动框选，不阻塞实时选择层。

## 配置和兼容策略

拟新增显式选项（设计草案，当前尚不可调用）：

```ts
await window.electronSnapora.capture({
  display: 'all',
  interactionMode: 'live',
});
```

`display: 'all'` 表示在所有屏幕开放选择，最终仍只有一块屏幕和一个截图结果。
`interactionMode: 'live'` 表示选后采集；`frozen` 保留现有先冻结再选择的行为。
首版实现 Windows `all + live` 和单屏 `live`；`all + frozen` 暂不实现，参数校验明确拒绝，避免默默退成单屏。
默认仍是 `cursor + frozen`，demo 显式启用 `all + live`，保留旧单屏模式用于比较。旧调用方无须改动，Ping 不接入。
新参数同时更新公共类型、IPC 白名单、运行时校验和中英文文档。非 Windows 请求 live/all 明确返回不支持；不静默更改调用者的采集时机。

## 实施顺序与验收

1. **先验证排除捕获与画面切换。** 用自有测试窗口展示固定色块及动画，上叠明显遮罩；比较捕获像素，确认遮罩、边框、光标、黑块均不进入截图。验证刚启动立即点击，以及当前 Electron 捕获路径。若不通过，先解决捕获后端。
2. **实现单屏选后采集。** 拆开无帧选择与有帧编辑，复用标注与导出；测试取消、重复提交、双击复制、采集失败和迟到帧。双击期间的复制意图最多保留一次，帧就绪后执行，不能重复截图或导出。
3. **扩展到多屏统一会话。** A/B 往返、选中屏锁定、统一取消，加入候选刷新、混合 DPI 和显示拓扑处理。
4. **demo 对比与文档。** 默认新交互、默认 panel 粒度；提供旧模式比较，记录实际耗时和适用环境。

验收至少覆盖：A/B 来回移动且不需重新启动；拖动越界仍限制起点屏；100%/150%/200% 混合缩放、负原点和上下排列；快速启动/取消/重启；标注后改变选区；屏幕热插拔；候选超时与自由框选；各阶段 Esc；目标应用菜单/焦点变化；视频/动画内容为选后帧；默认旧模式不回退。

性能单独记录“触发 → 可框选”“触发 → 首个可用容器”“选区提交 → 标注可用”的 p50/p95，冷启动和预热后分别统计。
预热后可框选目标 p95 <=100ms、选后标注目标 p95 <=200ms，均为待验证目标，不是已有结果；UIA 首个容器耗时按 Lark、浏览器、Ping 的真实页面分别报告。
零闪烁需检查屏幕实际呈现，不能只依据窗口 visible/opacity：当前 prime 阶段已经可能 opacity=1，但图片尚未 ready。软件捕获又可能排除交互层，所以画面过渡还需人工观察或外部高帧率录屏。

本次方案没有实现以上功能，也未进行多屏实机或排除捕获验证。
